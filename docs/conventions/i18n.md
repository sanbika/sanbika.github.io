# 国际化（i18n）约定

本仓库基于 Hugo + PaperMod，支持 `zh-cn`（默认）/ `en` 双语。本文件沉淀双语维护中的稳定约定。学自 2026 年 i18n 收尾轮（搜索标题 / Giscus 语言 / 切换标签 / 英文项目页 / 站点 i18n 副本）。

## 1. 内容页面

- **内容语言由作者每篇自主决定，单语页面是正常状态**。本仓库的实际情况是：读书笔记多为中文，偶尔直接用英文写，不追求双语全覆盖——不要为了凑双语而额外翻译，单语是常态。
- **`.en.md` 配对仅用于确实需要双语的页面**（如 `about/`、`projects/sample-project`）。一旦判定为双语页面，新增内容页必须同时提供双语：中文为主版本（`xxx.md`），英文为镜像版本（`xxx.en.md`），front matter 字段需一一对应（`title` / `date` / `draft` / `description` / `weight` / `comments` / 等）。slug 由 Hugo 按 `defaultContentLanguageInSubdir` 自动分配，不会冲突（默认中文在根 `/projects/sample-project/`，英文在 `/en/projects/sample-project/`）。
- **UI 页面**（如 `content/search.md`）也走双语惯例，但**不写硬编码正文**——只声明 `title` 和 `layout`，由对应模板渲染。

## 2. UI 文案

- **用户可见字符串必须走 `i18n/<lang>.yaml`，不得在模板中硬编码**。硬编码会导致语言切换时残留源语言文案。
- **站点级 i18n 副本**（仓库根 `i18n/zh-cn.yaml`）的用途：覆盖主题默认翻译、防主题升级破坏 fallback 链。它应当与主题源 `themes/PaperMod/i18n/zh.yaml` **字节级一致**（除文件头注释外）。任何偏差需在文件头加注释声明同步策略（如 snapshot 范围、明确不同步的字段），否则升级主题做 `diff` 时会被误报为冲突。
- **主题子模块的 `i18n/*.yaml` 是上游源，不要直接编辑**。如需改主题文案，统一在仓库根 `i18n/<lang>.yaml` 覆盖。

## 3. 第三方组件语言

- 集成 giscus / disqus / algolia 等第三方组件时，**不要把语言码硬编码为"是 en 就 X，否则 Y"**。这种写法对未来增加第三语言是陷阱（所有非 en 都会落到 Y，组件显示错误语言）。
- 推荐写法：`cond (eq .Lang "en") "en" .Lang`，前提是值是组件支持的语言码枚举。若组件不支持某些语言码，应用 `if-else` 链枚举到默认值，并在文件头加注释说明支持范围。
- 当前 `layouts/_partials/comments.html` 是双语场景专用写法（见 [[current-state.md]] TODO），本轮评审已通过。

## 4. 配置文件

- `config/_default/languages.toml` 中 `languageName` 字段在 Hugo 0.164 已**弃用**，应改 `label`。本仓库当前仍用 `languageName`，下一轮清理时统一迁移（见 [[current-state.md]] TODO）。
- `config/_default/params.toml` 与 `config/_default/config.toml` **不应同时定义同一 `[params]` 字段**。新参数统一写在 `params.toml`，避免重复（详见 [[current-state.md]] TODO）。
